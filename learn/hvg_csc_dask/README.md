# HVG CSC/dask tutorial test suite

A self-contained, learning-oriented test suite that walks the highly-variable-genes
(HVG) code paths we added for **column-chunked CSC dask arrays**, using realistic
**on-disk** fixtures generated from `pbmc3k`.

These tests are intentionally *not* part of the scanpy test tree — they live under
`scanpy/learn/hvg_csc_dask/` and import scanpy from this fork checkout directly
(`../../src` is prepended to `sys.path`). They are meant to be stepped through in a
debugger to understand the flow, not to gate CI.

### Where this lives in git

This suite is committed only on the `learn/hvg-csc-dask` branch, which is cut from
the feature branch `feat/hvg-csc-dask-3862`. The eventual upstream PR is made from
the feature branch, so these learning files never appear in that PR — they exist to
share the learning off the main repo.

## Why this suite exists

scanpy already ships a row-chunked, CSR-ish on-disk fixture
(`scanpy/tests/_data/10x-10k-subset.zarr`). Nothing on disk represents the **CSC,
column-chunked** layout our new HVG code targets. This suite fills that gap by
materializing the states a real user would have once CSC column-chunked HVG exists.

"Column-chunked" is realized at **read time**, not on disk: the store holds a plain
CSC component, `read_elem_lazy` returns a dask array with a CSC `_meta`, and
`.rechunk((-1, gene_chunk))` produces the gene-axis chunking our implementation
handles.

## Fixture manifest

Generated by `build_fixtures.py` (git-ignored, under `data/`):

`data/pbmc3k_hvg.zarr` — one AnnData built from `pbmc3k()[:1500, :1000]` then
`filter_genes(min_cells=1)` (final shape ~`1500 x 564`):

| element           | contents                                         | consumed by            |
| ----------------- | ------------------------------------------------ | ---------------------- |
| `X`               | `log1p(normalize_total(target_sum=1e4))`, **CSC**| `seurat`, `cell_ranger`|
| `layers["counts"]`| raw counts, **CSC**                              | `seurat_v3`, `seurat_v3_paper` |
| `obs["batch"]`    | categorical `{"a","b"}` (tiled)                  | batched HVG            |
| `var_names`       | deterministic `gene_0000...`                     | stable comparisons     |

Rebuild any time with:

```bash
python build_fixtures.py --force
```

## Scenarios (per-file call-stack notes)

Each test module has a top docstring mapping the call stack to breakpoint targets.

- `test_dispersion_ooc.py` — `seurat` / `cell_ranger` on lazy CSC `X`.
  `_main.py` dispatch → `_dispersion.py::_highly_variable_genes_single_batch` →
  `expm1` (seurat only) → `stats.mean_var` → `_get_mean_bins`/`_get_disp_stats` →
  `_subset_genes`/`_nth_highest`.
- `test_seurat_v3_ooc.py` — `seurat_v3` / `seurat_v3_paper`, single + batched, on
  lazy CSC `layers["counts"]`. `_seurat_v3.py::_raise_if_unsupported_dask_chunking`
  → `stats.mean_var` → per-batch `aggregate` (`get/_aggregated.py::aggregate_dask`,
  column-chunked branch) → `loess` → **new** `clip_square_sum` feature-chunked
  branch (`_clip_square_sum_feature_chunked`) → rank/select.
- `test_full_pipeline_ooc.py` — `normalize_total` + `log1p` + HVG end to end.
  Documents that `normalize_total` converts an **in-memory** CSC to CSR
  (`preprocessing/_normalization.py:257`) while the **dask** array keeps its CSC
  meta + column chunking; results still match.
- `test_dask_executor.py` — the `seurat_v3` column-chunked computation executed on
  a real `distributed.LocalCluster` (2 worker processes). Asserts correctness plus
  that tasks actually ran on the cluster.

## Running

From this directory (`scanpy/learn/hvg_csc_dask/`):

```bash
python -m pytest -q
```

Any interpreter with this fork importable works. Two common options:

- Standalone venv:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ../..            # this scanpy fork
pip install -r requirements.txt # distributed, scikit-misc, pytest, ...
python -m pytest -q
```

- An existing environment that already has scanpy's test deps (e.g. one used for the
  fork), pointed at this folder: `path/to/python -m pytest -q`.

The local `pytest.ini` keeps this suite off scanpy's own `addopts`
(`--doctest-modules`/`--pyargs`/plugin). The `hvg_store` session fixture auto-builds
`data/pbmc3k_hvg.zarr` if it is missing, so a clean checkout just works.

## Debugging tips

- Open any `test_*.py` and set breakpoints at the call-stack targets in its
  docstring; run the single test with your editor's debugger.
- Column-chunking assertions (`chunksize[1] != shape[1]`) are in the tests and in
  `_support.load_lazy_csc`, so you can confirm the layout before stepping in.
- For the executor scenario, `dask_client` in `conftest.py` builds the cluster; the
  task stream captured in the test confirms work ran on workers.

## Dependencies

See `requirements.txt`. scanpy itself is imported from this fork checkout (no install
strictly required); the extras are `distributed` (real scheduler for scenario 4) and
`scikit-misc` (loess for the seurat_v3 flavors).
